## TL;DR

Keep important text in HTML when its presentation can be achieved there.
Real text translates and reflows; image alternatives still depend on context.

## Key points

- Keep essential copy as selectable text.
- Let translations change length and layout.
- Use image alternatives based on purpose.
- Preserve contrast over artwork in every crop.
- Check the experience when images do not load.

## Trade-offs

| Approach          | Strengths              | Weaknesses       |
| ----------------- | ---------------------- | ---------------- |
| HTML text         | Reflow and translation | Layout work      |
| Text in artwork   | Fixed composition      | Poor adaptation  |
| Image alternative | Nonvisual meaning      | No visual reflow |

## Interview questions

<InterviewQuestion question="Does alt text replace real visible text?">

No: it helps provide a text alternative but does not let the visible lettering reflow, resize independently or translate in the same way.
Prefer real text when the desired presentation can be achieved with text and styling.

</InterviewQuestion>

<InterviewQuestion question="Are logos always prohibited?">

No: the relevant images-of-text criteria have exceptions for essential presentations, including logotypes.
Apply the criterion in context and still provide a meaningful accessible name where the logo serves as a control or link.

</InterviewQuestion>

<InterviewQuestion question="What about a complex chart?">

Keep the chart when the visualization is useful, with an appropriate alternative and access to the relevant explanation or data.
Do not flatten its important message into an unexplained bitmap and assume a file name is sufficient.

</InterviewQuestion>

<DeepDive>

### How it works

Real text exposes character content to translation systems, assistive technology, selection and adaptive layout.
A bitmap couples lettering to a fixed pixel composition and can become unreadable when its containing image is reduced.
If text sits over an image, assess actual background contrast across responsive crops and states rather than testing one screenshot.
The alternative for an image depends on its purpose in the page, including whether adjacent real text already supplies the same information.
A workflow that genuinely requires localized artwork also needs version tracking so visible images and text alternatives do not drift across locales.

### Edge cases

- A decorative image with duplicated visible heading text can produce redundant announcements if given the same alternative.
- A meaningful screenshot may require descriptive context rather than reproducing every pixel as a long alt attribute.
- A crop can move bright artwork behind a heading and invalidate a previously acceptable contrast combination.

### Common mistakes

- Baking the only actionable message into a background image.
- Using alt text as a substitute for a readable visual presentation.
- Assuming one translated image asset scales to every locale and viewport.
