## Key points

- Distinguish progressive files from adaptive streams.
- Verify container and codec support together.
- Choose quality from buffer and throughput evidence.
- Bound retained buffers and clean up resources.
- Provide captions and usable playback recovery.

## Trade-offs

| Approach          | Strengths          | Weaknesses         |
| ----------------- | ------------------ | ------------------ |
| Progressive file  | Simple delivery    | Limited adaptation |
| Adaptive segments | Quality switching  | Player complexity  |
| Low-latency live  | Near-live feedback | Less buffer margin |

## Interview questions

<InterviewQuestion question="Must the whole video download before playback?">

No: progressive delivery and byte-range support can allow playback before the full resource arrives.
Adaptive streaming adds a manifest and rendition or segment selection policy beyond that basic behavior.

</InterviewQuestion>

<InterviewQuestion question="What drives adaptive bitrate selection?">

Estimate sustainable delivery and available buffer while considering decoding capability, viewport and explicit quality preferences.
Avoid treating a single bandwidth sample or connection label as a reliable permanent budget.

</InterviewQuestion>

<InterviewQuestion question="What must be cleaned up when the player unmounts?">

Stop owned requests and listeners, release relevant media or MSE resources and revoke owned object URLs.
Also bound retained buffers during long playback so a successful stream does not grow memory indefinitely.

</InterviewQuestion>

### How it works

A media container and its encoded audio or video codecs are separate compatibility choices.
Adaptive protocols describe available renditions and time-aligned segments so a player can change quality without restarting the whole task.
MSE lets JavaScript supply media data to a browser playback pipeline, but it does not provide the manifest parser, adaptation algorithm or full error recovery itself.
Appending to a SourceBuffer requires coordination with its update lifecycle, codec support and buffer limits.
For live media, end-to-end latency includes capture, encoding, segmenting, distribution and player buffering; reducing one layer can reduce resilience elsewhere.

### Edge cases

- Autoplay can be blocked, so playback initiation needs a rejected-promise recovery path.
- A live window can move past the user's paused position and require an explicit resume policy.
- Cross-origin media or segment fetching needs the appropriate CORS and credential configuration for its access path.

### Common mistakes

- Assuming an mp4 extension proves codec support.
- Calling MSE an adaptive streaming solution by itself.
- Ignoring caption, keyboard and memory behavior while optimizing bitrate.
