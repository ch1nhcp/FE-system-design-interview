## How to choose

Start from two questions: who sends data, and how quickly must it arrive?
If only the server sends and a few seconds of delay are fine, poll.
If only the server sends but updates must feel instant, use server-sent events.
If both sides talk often, use WebSockets.
Long polling is the fallback when neither streaming option gets through the network.

|                      | Short polling               | Long polling                   | Server-sent events                 | WebSocket                              |
| -------------------- | --------------------------- | ------------------------------ | ---------------------------------- | -------------------------------------- |
| Direction            | Client pulls                | Client pulls, server waits     | Server to client                   | Both ways                              |
| Latency              | Up to one interval          | About one round trip           | Immediate                          | Immediate                              |
| Wasted requests      | Many                        | Only on timeouts               | None                               | None                                   |
| Connection           | New request each time       | One held request at a time     | One long HTTP response             | One upgraded TCP connection            |
| Reconnect and replay | Not needed                  | Manual, with a cursor          | Built in                           | Manual                                 |
| Infrastructure       | Any HTTP server             | Async server, long timeouts    | HTTP without response buffering    | WebSocket-aware load balancer, pub/sub |
| Good for             | Job status, slow dashboards | Fallback, simple notifications | Feeds, notifications, AI streaming | Chat, collaboration, games             |
